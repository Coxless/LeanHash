### 定義と証明（`LeanHash/Spec/Fmix.lean`）

- `xsr s x = x ^^^ (x >>> s)`、`fmix64 = xsr 33 ∘ (· * c2) ∘ xsr 33 ∘ (· * c1) ∘ xsr 33`（Rust の `fmix64` と同じ）
- 逆関数 `fmix64Inv` は段を逆順に。逆元 `c1Inv = 0x4f74430c22a54005`、`c2Inv = 0x9cb4b2f8129337db`（Rust のテストにあった値）
- 乗算の打ち消し: `c * cInv = 1` は `decide`（具体値の計算）、あとは `BitVec.mul_assoc` と `BitVec.mul_one` だけ。**乗算は SAT に一度も渡していない**
- xorshift 33 の自己逆だけ `bv_decide`
- 定理: `fmix64Inv_fmix64`（左逆）、`fmix64_fmix64Inv`（右逆、`BitVec.mul_comm` で逆元の向きを入れ替え）、`fmix64_injective`、`fmix64_surjective`、`fmix64_bijective`

```
lean LeanHash/Spec/Fmix.lean   # 0.3〜0.6 秒
```

- 1回目: `Unknown identifier 'Function.Bijective'` → `Function.Bijective` は Mathlib の定義で、core にあるのは `Injective` / `Surjective` だけ。仕様層は Mathlib なしで済ませたいので、**`Injective ∧ Surjective`（Mathlib の定義の中身そのもの）で書いた**
- `#print axioms fmix64_bijective` → `propext, Classical.choice, Quot.sound, xsr33_involutive._native.bv_decide.ax_1_5`。`sorry` なし。最後の公理は bv_decide が SAT の証明書をネイティブ計算で検査した結果（`Mix.lean` と同じ信頼の範囲）。`c1_mul_c1Inv` は公理を一つも使っていない
- 速い（1 秒未満）のは、xorshift の SAT 問題が小さく、乗算を SAT に入れていないため

### Rust との照合

- 同じ 5 個のテストベクトル（0, 1, 2⁶³, 0x0123456789abcdef, 2⁶⁴−1）を Lean の `example ... := by decide` と Rust の `fmix64_matches_lean_vectors` に置いた。期待値は Python で計算
- `cargo test -p leanhash fmix64` → 2 passed
- 否定テスト: 期待値の 1 ビットを変えると `decide proved that the proposition ... is false` で失敗することを確認（検査が空回りしていない）


## 決めたこと

- 仕様層（`LeanHash/Spec/`）は、必要になるまで Mathlib を import しない。`Bijective` は `Injective ∧ Surjective` で書く
- 乗算定数の打ち消しは「`c * cInv = 1` を `decide` ＋ 結合則」の形で統一する。P2 以降の乗算も同じ方針
- Rust 側の手書きの `fmix64` は試作扱いのまま。Lean との一致はテストベクトルで確認するに留め、正式な一致は P3（HashIR から生成）で取る
