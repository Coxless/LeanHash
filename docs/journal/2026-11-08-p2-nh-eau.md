# 2026-11-08 P2 圧縮段：NH の ε-AU

ブランチ `p2-nh-eau`（P1 の `38af885` から派生）。

## 目的

- 固定長 NH が ε-AU（ε = 2⁻ʷ、w は語の幅）であることを Lean で `sorry` なしで証明する
- ゲート（CONCEPT 7 章）: ε-AU 定理と実測（8〜16bit の縮小版での全数照合）が一致すること

NH の定義（UMAC）: 語は w ビット、W = 2ʷ。
NH_K(M) = Σᵢ ((m₂ᵢ₋₁ + k₂ᵢ₋₁) mod W) · ((m₂ᵢ + k₂ᵢ) mod W) mod W²

### 1 組（2 語）の全数検査・Python 版（`bench/exhaustive/nh1_pair.py`）

各 (m₁, m₂) ≠ (m₁', m₂') と各 c について、f(m) − f(m') ≡ c (mod W²) となる鍵 (k₁, k₂) の数の最大値を数えた。

```
w=1: max collisions=2 (W=2), per-k1 max: both differ=1, only m1 differs=1
w=2: max collisions=4 (W=4), ...=1
w=3: max collisions=8 (W=8), ...=1
w=4: max collisions=16 (W=16), ...=1
w=5: max collisions=32 (W=32), ...=1
（`python3 bench/exhaustive/nh1_pair.py 5`、w=1〜5 で 6 分 14 秒。遅いので w=6 以上は Rust 版に回した）
```

- 衝突する鍵は最大でちょうど W 個 → **上界 2⁻ʷ は達成される（改善できない）**
- **m₁ ≠ m₁' なら、k₁ を固定したとき解 k₂ は高々 1 個**（m₂ が同じでも違っても）。証明はこの形に沿わせる

### 証明の組み立て（紙の上）

補題（単射性）: W > 0、a, a' < W、a ≠ a' とする。x(k) = (m₂ + k) mod W、x'(k) = (m₂' + k) mod W と置くと、
k ↦ a·x(k) − a'·x'(k) (mod W²) は k ∈ [0, W) 上で単射。

1. k, k̃ で値が等しいとし、d = x(k) − x(k̃)、d' = x'(k) − x'(k̃) と置く（整数、|d|, |d'| < W）
2. どちらも k − k̃ と mod W で合同なので d' ∈ {d, d − W, d + W}
3. a·d − a'·d' ≡ 0 (mod W²)
   - d = 0 なら d' ≡ 0 かつ |d'| < W より d' = 0。x が k について単射なので k = k̃
   - d' = d（d ≠ 0）: (a − a')·d は 0 でなく、絶対値は W² 未満なので W² の倍数にならない。矛盾
   - d' = d − W（このとき d > 0）: g = a − a' と置くと g·d + a'·W は −W² より大きく 2W² 未満。よって 0 か W² のどちらか
     - = W²: g·d = W(W − a')。a = a' + g < W から g < W − a'、よって g·d < (W − a')·W。矛盾
     - = 0: h = a' − a > 0 として h·d = a'·W。h ≤ a' かつ d < W から h·d < a'·W（a' = 0 なら h = 0 で矛盾）。矛盾
   - d' = d + W: k と k̃ を入れ替えると前の場合に帰着する
- W が 2 の累乗であることは使っていない → Lean では一般の W > 0 で証明する

全体の流れ:
1. 1 組: (m₁, m₂) ≠ (m₁', m₂') なら衝突する (k₁, k₂) は高々 W 個。m₁ ≠ m₁' なら補題を k₁ ごとに使い、m₁ = m₁' なら積の順序を入れ替えて対称に扱う
2. n 組: M ≠ M' なら、違う組 i 以外の鍵を固定すると残りの和は定数 c。1 組の結果より、衝突する鍵は高々 W^(2n−1) 個。つまり確率 ≤ 1/W

### Lean での形式化

ファイル:
- `LeanHash/Spec/NH.lean`: `pairVal`（1 組の積）と `nh`（値は `ZMod (W^2)`）。語は `Fin W` なので `m.1 + k.1` がそのまま mod W の加算
- `LeanHash/Props/NHCore.lean`: 紙の上の補題の整数部分（`core_shift`、`core`）
- `LeanHash/Props/NH.lean`: `inj_second` → `pd_inj2` / `pd_inj1` → `pd_eq_of_agree` → `nh_eau`、確率の形の `nh_eau_prob`、W = 2ʷ の `nh_eau_pow2`

主定理:

```lean
theorem nh_eau (M M' : Fin n → Fin W × Fin W) (hM : M ≠ M') :
    (univ.filter fun K => nh K M = nh K M').card * W ≤ W ^ (2 * n)
theorem nh_eau_pow2 (w : ℕ) (M M' : Fin n → Fin (2 ^ w) × Fin (2 ^ w)) (hM : M ≠ M') :
    (#{K | nh K M = nh K M'} : ℚ) / Fintype.card (Fin n → Fin (2 ^ w) × Fin (2 ^ w)) ≤ 1 / 2 ^ w
```

数え上げの方法: 衝突する鍵の集合を S とし、(K, t) ↦「組 i の、ずらしてよい方の鍵に t を足した鍵」が S × Fin W 上で単射であることを示して |S|·W ≤ |鍵全体| を得た（`card_mul_le_of_inj`）。確率空間や fiber ごとの和を持ち出さずに済んだ。

詰まった点（すべて解決）:
- `core` の不等式評価はほぼ `nlinarith` が一発で通した。乗算は `nlinarith`（実数・整数の非線形算術）で処理しており、`bv_decide` は使っていない
- `push_neg` は Mathlib v4.35.0 で非推奨（`push Not` に置き換え）
- `omega` が `(↑m2 + ↑k) % ↑W ≥ 0` を知らず失敗 → `fin_bound`（Fin の値は 0 以上 W 未満）を明示的に仮定に入れて解決
- `rw [← Fintype.card_fin W]` が `nh K M` の型の中の W まで書き換えようとして motive エラー → `suffices` で目標の形を先に決めて回避
- `positivity` が `W^(2n) > 0` を示せない（W = 0 の可能性がある）→ `NeZero W` から `pow_pos`

## 追記（2026-11-09）：上界が tight であることの意味と、構成についての決定

### なぜ 1/W より縮められないか

- 1 語目だけ違う組（例: M = (0, 0)、M' = (1, 0)）では、(m₂ + k₂) mod W = 0 になる k₂（W 通り中 1 通り、k₁ は任意）で右の因数が 0 になり、1 語目の違いが 0 倍で消える → 衝突確率はちょうど 1/W
- 全数検査で 16bit の δ = (1, 0)、(0, 1)、(0x8000, 0) がちょうど W 個衝突したのはこの仕組み
- この議論は W によらないので、W = 2⁶⁴ でも最悪はちょうど 2⁻⁶⁴。**Lean ではまだ証明していない**（下限の定理として足すのは数行の見込み）
- 一般のハッシュ族では、出力 N 通りなら ε はおおよそ 1/N が下限（Stinson の下界）。NH の出力は W² 通りなので下限は約 1/W² だが、NH は 1/W。速さ（2 語に乗算 1 回）の代わりに出力の半分ぶんの強さを捨てている
- ε を下げるには証明の工夫ではなく構成を変えるしかない（語を広げる、NH を 2 本並べる、別の段と組み合わせる）
