## v2c の 1KB 以下の構成（`rust/leanhash/src/v2.rs` を読んで整理）

鍵: NH 用 130 語（u64）、multiply-shift の乗数 m（奇数の u128）、fin（u64）。

| 経路 | 長さ L | 計算 |
| :--- | :--- | :--- |
| A | 0〜32 | NH64（W = 2⁶⁴、和は mod 2¹²⁸）。データの組は 0〜2 個（組 0, 1）、長さの組 (L, 0) は鍵の組 64（語 128, 129）に固定 |
| B | 33〜1024 | NH32 の Toeplitz 2 本（W = 2³²、和は mod 2⁶⁴）。レーン i は鍵レーン i と i+1。データのレーンは ⌈L/8⌉ 個、長さのレーン (L, 0) はレーン 128 に固定。出力 (x, y) を y·2⁶⁴ + x の 128bit に |
| 共通 | | acc（128bit）→ `ms(m, acc) = hi64(m·acc mod 2¹²⁸)` → `^ fin` → fmix64 |

### 気づいたこと 1：組の数が違う場合は、長さの組で片づく

P0' の journal では「組数が違う 2 入力の NH は約 2⁻⁶³」と見込んでいた。しかし長さの組（レーン）は**長さによらず同じ位置**（組 64 / レーン 128）にあり、
長さが違えば必ずそこが違う。「両方にあって値が違う位置のうち一番後ろ」を j とすれば、j より後ろは両方同じなので、
組の数が違っても同じ長さの場合と同じ議論で ε = 2⁻⁶⁴ になる（片方にしかない組は j より前にあり、定数として扱える）。

### 気づいたこと 2：経路をまたぐ衝突（A の入力と B の入力）は、今の v2c では証明できていない

- A と B は同じ鍵語を別の形（NH64 と NH32×2）で使い、同じ m と fin で仕上げる
- 長さの組の 2 語目の鍵 k₁₂₉ だけを動かすと、acc の下位 64bit の条件は (L_A + k₁₂₈)·k₁₂₉ ≡ d（mod 2⁶⁴）。解の数は 2^(v₂(L_A + k₁₂₈)) 個で、k₁₂₈ について平均すると約 33 個 → 下位だけでは約 2⁻⁵⁹。上位 64bit も合わせればもっと小さいはずだが、きれいな上界の議論が見つからない
- 案: **経路ごとに独立な fin を使う**（fin_A、fin_B、長い入力用）。経路が違う 2 入力の衝突は `u ^ fin_A = v ^ fin_B` で、fin_A が一様なら確率はちょうど 2⁻⁶⁴。速度への影響はない（定数が違うだけ）。ただし B と長い経路の出力が変わるので、SMHasher3 の検証値（0xAEF37E4F）が変わる
- → Lean では「同じ経路の 2 入力」と「経路ごとに fin が独立なときの経路またぎ」を分けて示す。Rust 試作を変えるかはユーザーに確認する

## 試したこと

### 1. Toeplitz 2 本（`LeanHash/Props/Toeplitz.lean`）

- 証明は P2 の `nh_eau` と同じ「1 か所の鍵をずらす写像が単射」の数え上げ。これを抽象化した:
  - `card_single`：Σ Dᵢ(Kᵢ) = 0 の鍵の数 × |T| ≤ 鍵の総数（位置 j の D_j がずらし s について単射なら）
  - `card_toeplitz`：2 本目は鍵 Kᵢ₊₁。j より後ろの差が 0 なら、K_j と K_{j+1} の 2 か所をずらして |T|² 倍
  - 要点: j を「値が違う最後の位置」に取ると、1 本目の和で K_j が決まり（K_{j+1} は 1 本目には位置 j+1 でしか出ず、そこは差 0）、そのあと 2 本目の和で K_{j+1} が決まる
- レーンの有無つき NH `nhO` / `nhT`（`Option`、ない組は 0）。仮定は `LastDiff`（両方にあって値が違う最後の位置 j があり、j より後ろは同じ）
  - `nhO_eau`：1 本は (1/W)-AU（両方にあって値が違う組が 1 つあればよい）
  - `nhT_eau`：Toeplitz 2 本は (1/W²)-AU
  - `exists_lastDiff`：有無の並びが同じで違うメッセージには `LastDiff` の位置がある
- 行き止まり: 集合の書き換えに `convert h using 3` を使ったら、`ZMod` の `DecidableEq` インスタンスが食い違ってエラーになり、しかも 1 ファイルのビルドに **235 秒** かかった。`Finset.filter_congr` で集合を明示的に書き換える形に直したら 5 秒
- 全数照合（`python3 -I bench/exhaustive/p2_rest_check.py`）: 語 1〜2bit、レーン 1〜3 個で、最悪の衝突数は上界とちょうど一致（b=1 n=3: 64 = 2⁸/2²）

### 3a. multiply-shift（`LeanHash/Props/MultShift.lean`）

- `ms_au`：x ≠ y（< 2ʷ）なら、衝突する奇数 a は 2^(w−l) 個以下。`ms_au_prob`：確率 ≤ 2/2ˡ = 2^(1−l)。w = 128、l = 64 で 2⁻⁶³
- 証明: d = x − y = 2ᵗ·u（u 奇数）。衝突なら r = a·d mod 2ʷ = 2ᵗ·z は 0 の近く（r < 2^(w−l) か r > 2ʷ − 2^(w−l)）
  - t ≥ w − l なら起こらない（r は 2ᵗ 以上 2ʷ − 2ᵗ 以下）
  - t < w − l なら z（奇数）は [0, R) か (2^(w−t) − R, 2^(w−t)) にある（R = 2^(w−l−t)）。a ↦ (a / 2^(w−t), 詰めた z) が単射で、値は 2ᵗ·R = 2^(w−l) 通り
  - u が奇数なので 2^(w−t) と互いに素 → z から a mod 2^(w−t) が決まる（`Nat.ModEq.cancel_right_of_coprime`）
- 文献（Dietzfelbinger 1996）は読めない環境なので、自分で組み立てた
- 全数照合: w = 4〜8、l = 1〜4 で最悪の衝突数は w=4,l=3 以外で上界とちょうど一致（w=4,l=3 は 1 ≤ 2）
