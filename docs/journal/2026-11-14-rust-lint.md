# Rust の fmt / clippy を通す

## 目的

workshop の `check`（`cargo fmt --all --check && cargo clippy --workspace -- -D warnings && cargo test`）が、
main の時点で fmt と clippy で止まっていた（[2026-11-14-p3-outer](2026-11-14-p3-outer.md) で気づいたもの）。これを通す。

## 環境

- rustc 1.97.0、rustfmt 1.9.0、clippy（`rust-toolchain.toml` で固定）。Intel Xeon @ 2.10GHz（AVX2 あり）、4 vCPU

## 試したこと

### fmt

- `rustfmt.toml` がなく、既定の幅 100 で整形されていなかった（コードは幅 120 前後で手書きされていた）
- 設定ごとの差分の量（`cargo fmt --all` → `git diff --shortstat`）:

| 設定 | 差分 |
| :--- | :--- |
| 既定（幅 100） | 4 ファイル、+200 / −58 |
| `max_width = 120` | 4 ファイル、+96 / −59 |
| `max_width = 120` ＋ `use_small_heuristics = "Max"` | 4 ファイル、+54 / −104 |

- 3 つ目が差分最小で、既存の 1 行の `if … { … } else { … }` などをそのまま保てる → これを採用し `rust/rustfmt.toml` に置いた
- `kernel.rs`（生成物）は `#[rustfmt::skip]` なので変わらない（`lake exe emit_rust | diff` で確認）

### clippy

- `cargo clippy --workspace --all-targets -- -D warnings` の指摘は 1 件だけ:
  `v2.rs` の `body.len() % 32 != 0` が `manual_is_multiple_of`（rustc 1.97 の clippy で入った lint）
- `!body.len().is_multiple_of(32)` に書き換え（`usize::is_multiple_of` は 1.87 で安定化。ツールチェインは 1.97 固定）
- AVX2 の `cfg` のコードは `RUSTFLAGS="-C target-cpu=native"` のときだけ検査されるので、そちらでも clippy を回した → 指摘なし

## 結果

- `cargo fmt --all --check`：通る
- `cargo clippy --workspace --all-targets -- -D warnings`：既定・`-C target-cpu=native` の両方で通る
- `cargo test --workspace`（debug）、`RUSTFLAGS="-C target-cpu=native" cargo test --workspace --release`：26 passed。
  切り替え前の出力の畳み込み（`golden::matches_handwritten_kernels`）と Lean の参照実装のベクトル（`lean_ref`）も一致のままなので、値は変わっていない
- `lake exe emit_rust | diff - rust/leanhash/src/kernel.rs`、`lake exe ref_vectors | diff - …`：差分なし

## 決めたこと

- Rust の整形は `rust/rustfmt.toml`（幅 120、`use_small_heuristics = "Max"`）に従う
